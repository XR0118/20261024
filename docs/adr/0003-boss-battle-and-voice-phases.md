# ADR-0003: Boss 战架构 —— 语音阶段细分、数值引擎本地化、记忆注入

日期：2026-10-23
状态：已接受

## 背景

核心跑酷 demo 完成后，为最大化"灵矽应用"的 AI 呈现（评分 15%）与产品故事（50%），
终局玩法确定为 Boss 猜数字对决（Bulls & Cows + 攻击-格挡 QTE）。三个既有决策被触动：

1. ADR-0002 规定跑酷期间断开灵矽会话省计费，但 Boss 战需要游戏中的语音交互；
2. Boss 的猜数智能与复盘数据来源存在"灵矽平台 LLM 看不到游戏状态"的鸿沟；
3. 主持人/Boss/教练三人格与"一台设备只能绑一个智能体"的平台约束冲突。

## 决策

**1. 语音会话生命周期按玩法阶段细分**（修订 ADR-0002 的两态模型）：

| 阶段 | 语音会话 | 麦克风 |
|---|---|---|
| 待命 | 保持连接 | 上行（唤醒+指令） |
| 跑酷 | 断开（省计费） | 仅本地响度判定 |
| Boss 战 | 保持连接 | 上行（报数/投降/QTE 喊声走本地响度） |

**2. Boss 数值引擎本地化**：猜数（候选集信息熵贪心）、位数判定、亮位、胜负判定全部在
golang 内完成——可测试、演示零翻车。灵矽承担全部语音层：ASR 听玩家报数（含中文数字）、
TTS 播 Boss 台词，人格由提示词驱动。Boss 不经平台 LLM 做数值推理。

**3. 复盘数据经长期记忆 API 注入**：局终 golang 以 REST 写记忆片段
（按设备 MAC 归档）到教练智能体的灵矽长期记忆；复盘时教练 LLM 自动取用。
不引入 MCP，不要求公网可达。

**4. 三人格先用单智能体承载**：智控台一个智能体的提示词包含主持人/挑战者/教练三重
人格（报数、攻击、复盘各有指令词上下文）。golang 预留 AgentRouter 接口（当前恒返回
同一 agent），未来动态换绑为独立智能体时无需改动调用方。

## 后果

- 攻击-格挡的"喊声"用本地响度判定（不依赖 ASR，零延迟）；报数/投降用 ASR 语义
- 中文数字解析（"三七八"/"378"）是 golang 的固定职责，需覆盖口语变体
- 玩家格挡成功后可换数：Boss 的候选集重置——竞速张力来自 Boss 逼近速度 vs 玩家亮位情报积累
- 复盘依赖用户在智控台创建 API-KEY 并为教练智能体开启长期记忆
- 动态换绑（真三智能体）与"Boss 大脑上移平台 LLM（MCP）"均进 roadmap

## 修订（2026-10-24，T4 落地）

设备协议实测（spike，结论在 #16）：`listen detect` 带 `text` 会被平台
当作一轮用户话语送 LLM——事件注入人格可行；带 `text_response` 则内容
逐字播出；新 detect 会打断未播完的 TTS。据此把决策 2 细化为双通道：

- **关键信息事件**（Boss 报数、命中数、亮位、攻击宣告、胜负结算）：
  本地模板 + `text_response` 逐字直发——报数数字零失真（378 必须读
  「三七八」）、延迟最低。这部分主动台词不再经平台 LLM，是对原决策
  「人格由提示词驱动」的显式收窄。
- **氛围事件**（开局宣告、换数抉择）：`detect` + 事件标记 → 平台 LLM
  挑战者人格发挥（原决策路径保留）。
- 玩家开口的应答式反应仍全走平台 LLM（不变）。
