# ADR-0002: golang 作为唯一后端 —— 自实现灵矽设备协议，退役 linx_app

日期：2026-10-23
状态：已接受

## 背景

ADR-0001 过渡期用开源 C++ 客户端 linx_app 当"设备"（Mac 直连灵矽），游戏指令靠
linx_app 截获 stt 文本后 HTTP POST 本地 `/intent` 转发。该路线已跑通，但存在三个结构性问题：

1. 双进程抢一个麦克风（linx_app 与网页游戏各持一路 getUserMedia），演示需耳机防串音
2. 演示形态是"浏览器 + 终端"两件套，观感割裂
3. stt → 意图 → 游戏动作跨进程跨协议（WS→HTTP→WS），链路冗长

同时复查发现：原方案的"第三方应用接入"要求灵矽云公网回调我方服务，
"云端 MCP"同样要求公网可达——两者都引入了不必要的公网依赖；
而灵矽会把 ASR 文本（stt 消息）直接下发到设备端，设备端在本机即可截获。

## 决策

**golang 进程自实现灵矽设备协议，成为唯一后端；浏览器成为唯一前台。**

```
浏览器（唯一前台）
  麦克文流 ──┬→ WebAudio 音量判定 → L0 跳跃（本地，<50ms）
             └→ OPUS 编码（WebCodecs）→ WS → golang
golang（唯一后端）
  ├→ OTA 取 token，直连灵矽 WS，自称设备（MAC 98:a3:16:f9:d9:35）
  ├← stt 文本 → classify() → 游戏动作 → 推浏览器（进程内直达）
  ├← TTS OPUS 帧 → 转发浏览器解码播放
  └→ 台词由灵矽平台 LLM 生成（智控台提示词，见 docs/prompt-host.md）
```

- 语音台词：灵矽平台 LLM + 主持人提示词，不引入自备 LLM、不需要公网
- 意图识别：stt 文本本地关键词匹配，服务"开始/换图/成绩"等指令
- 编解码（OPUS 上/下行）都在浏览器完成，golang 纯转发与协议编排，零 cgo
- 保留 ADR-0001 的第三方接入端点作为 L3 增强与降级路径

## 后果

- linx_app（C++ 客户端）退役；其 stt 截获补丁与构建补丁仅存于本机副本
- 麦克风单源：一个 getUserMedia 同时喂音量判定与语音上传，串音问题消除
- 新增协议实现风险：帧格式（60ms 声明 vs 浏览器 20ms 编码输出）、
  listen/tts 状态机（TTS 播放期停上行防回音）需联调验证
- 若 WebCodecs opus 帧不被服务端接受，回退方案为 opus wasm 编码库
