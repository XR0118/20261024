# ADR-0001: 双通道架构 —— 本地音频判定与灵矽语义大脑分离

日期：2026-10-23
状态：已接受

## 背景

议题要求"语音类游戏"，设计目标是"节奏天国"式的声控游戏体验。核心矛盾：

- 节奏/音高判定需要 **<100ms** 延迟（onset、音量包络是信号处理，不走 ASR）
- 灵矽链路为 ASR→LLM→TTS 对话回路，官网宣传响应 <600ms，语义往返在秒级

用灵矽链路做实时游戏判定体验必死；反过来若游戏全在本地做，灵矽沦为摆设，
"灵矽应用"的题面契合与 AI 价值呈现（评分 15%）都会落空。

## 决策

**双通道分工**：

1. **实时通道（本地）**：浏览器 Web Audio API（getUserMedia + AnalyserNode）
   做音量包络检测（<50ms），直接驱动跳跃力度。不经任何网络。
2. **语义通道（灵矽）**：主持、关卡生成、Boss 人格、点评全部走灵矽，
   延迟不敏感，通过**第三方应用接入模式**落地——平台把设备语音 POST 到
   我们的 golang 端点，我们按游戏实时状态生成台词，SSE 流回，平台 TTS 播出。

**为什么不选云端 MCP 作为大脑主通道**：MCP 适合 LLM 调用无状态工具；
主持与 Boss 需要"对话轮次 + 游戏状态 + 台词风格"的完整控制权，
第三方应用接入模式下大脑就是我们的后端，LLM 选型与提示词完全自主。

**四层灵矽含量（L0→L3 递增）**，每层独立可演示、逐级降级：

- L0：纯本地声控跳跃——永远可玩的保底
- L1：灵矽主持开场 + 结算点评
- L2：LLM 按音乐/主题生成关卡 JSON，游戏动态加载
- L3：AI Boss 实时嘴炮（游戏事件 → 台词）+ 回合间战术决策

**语音入口升级路径**：D1 用开源 linx-linux C++ 客户端（Mac 当设备，
零协议风险）；D2 视进度升级为 iPhone 灵矽小程序（麦克风物理分离，
演示形态最佳）或网页自实现设备协议（单页一体化，工程风险最高）。

## 后果

- 前端选型 Phaser 3 + Vite + TypeScript：physics/sprites/场景管理开箱即用，
  训练语料充足（AI 生成代码质量高）
- 麦克风为双消费者（C++ 客户端 + 网页），演示需戴耳机防 TTS 串音
- 真节奏玩法（严格时机判定）超出本期范围，"节奏感"由表现层
  （BGM、节拍 UI、PERFECT/GOOD 判定、连击、加速关卡）承担
- 多人联机不做：灵矽平台无房间/群组能力（调研结论），自建 SFU 超 3 天预算
